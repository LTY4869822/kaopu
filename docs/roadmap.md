# 从本地复习工具到完整学习平台

本路线图以用户希望的「实用、便捷、有效，支持文档理解、速成复习、跨科规划和理工科练习」为目标。当前交付建立了可运行的闭环；下面的后续阶段不是已经完成的能力，也没有经过真实学生实验来证明提分效果。

## 本次已经可以运行的版本

| 环节 | 现有能力 | 边界 |
| --- | --- | --- |
| 课程与考试 | 新增/编辑/删除课程、考试日期、目标及每日容量 | 单用户状态；没有学校教务系统同步 |
| 资料整理 | 批量导入并按文件名/正文规则自动归科，PDF/DOCX/PPTX/TXT/MD提取，按需使用本机Docling版面/OCR/表格管线，保存受登录保护的原文件 | 公式富化关闭，识别仍需核对；Word按节引用，不编造物理页码 |
| 内容查找 | 本地中文词项/BM25 类检索，可选模型辅助讲解 | 没有向量检索；模型调用不是答案正确性证明 |
| 复习规划 | 截止日保障与滚动分配，支持目标、难度、工作量、每周容量、单日例外和时间线/每日双模式 | 评估未来90天；启发式，不做成绩预测；考试日整日预留 |
| 理解与练习 | 原文回忆、模型理解题、六题型自定义卷、历年卷模板确认和仿真、讲练/限时答卷、分层提示、复盘与来源 | 来源核验和固定答案匹配不证明科学正确，主观题待核对；没有通用符号证明或准确率承诺 |
| 错题回流 | 独立练习错题筛选，试卷报告记录学生确认的错因、生成针对性新卷，并收进记忆卡 | 不冒充自动诊断；自评不覆盖确定性判分，不将重复/辅助作答当新掌握证据 |
| 长期记忆 | 实际调用 ts-fsrs，保存评分状态与下次到期时间 | 默认参数；没有针对个人日志训练，记忆不等于解题能力 |
| 设备体验 | 桌面与手机响应式界面，本地账户认证，可访问同一本机服务 | 没有多用户隔离或云同步；局域网访问共享一份数据 |

原文回忆题使用稳定内容标识防重复添加。相同题目重复作答不重复提升掌握估计。它们是确定性功能，不需要模型密钥。

当前实际依赖见 `package.json` 和 `requirements-docling.txt`。**Docling已在隔离Python环境接入，RAGFlow、pyBKT仍为研究参考**；DeepTutor等教学项目借鉴其契约与证据设计，未整体安装其运行时。不能把上游全部功能写成考谱已经拥有的能力。

自动归科已经实现可解释规则分类、未知资料人工确认、独立子科保留和内容去重；后续仍需真实专业资料评测、语义分类及合订资料拆分，而不是宣称已实现任意学科识别。

## 第一阶段：可靠的个人学习数据与多人基础

先把单用户 JSON 数据迁移为带版本的数据库模型，建立用户、课程、文件、知识点、练习、作答、复习事件的稳定 ID。引入账号鉴权、服务端对象级权限、设备会话和配额。原始文件进入受限对象存储，解析产物与原文件拥有一致的访问与删除规则。

云同步需要冲突策略与幂等事件：离线重复提交不应双计时长或重复排期；同一张卡片在多个设备复习时，必须保留顺序和可审计的处理结果。增加导入、版本迁移、备份和恢复演练。

验收：两个测试账号无法读写彼此课程；多设备重复提交只生效一次；网络恢复后数据一致；备份可恢复；删除课程和原文件后关联数据按产品规则处理。通过前不作为公开多人服务上线。

## 第二阶段：可信的文档理解

为大文件建立异步队列、任务状态、取消、超时、重试和资源上限。评估 OCR 与版面解析方案，分别测量中文文本、公式、表格、图表、扫描件的质量；Docling 可以作为候选方案之一，但必须用真实课程资料测试后再选型。

建立「文件 → 页/幻灯片/段落 → 版面区域 → 文本/公式 → 知识点」定位链，提供原件对照。公式和图表识别低置信时应请求核对，不能把乱码当作有效知识。知识点提取、考纲匹配和重要性建议都应显示依据；将老师确认的范围与算法推测分开。

验收：固定评测集有字符错误率、公式结构正确率、表格提取准确率和来源定位准确率；用户能从结论定位到原件；失败任务可重试，且不会阻塞其他用户。

## 第三阶段：诊断知识缺口与建立学习路径

从课程级简单估计推进到知识点级诊断。先由课程大纲和教师审核定义知识点、先修关系、题型与难度，再收集无提示答题、提示使用、耗时、隔日变式表现和错误标签。个人自评、翻卡和阅读完成应作为弱证据，独立变式答对作为更强证据。

BKT 等知识追踪模型是候选，不应在数据不足时盲目替换透明规则。用独立留出的作答记录比较基线、检查校准误差与不同专业的偏差；对新课程、新学生显示估计的不确定性。先修缺口应导向一个最小补课动作，而不是推荐整门视频课。

验收：诊断与人工标注在可接受范围内一致；明确区分未测和不会；学生能解释为什么收到当前建议；不同题目的新证据能够改变学习路径。

## 第四阶段：可验证的理工科练习与错因

保留当前原文回忆题作为记忆工具，另外建立计算、推导、建模题的生成与审核流程。每题包含知识点、前置条件、有效域、标准答案、可核查步骤及来源。针对合适题型接入符号计算、数值验证或受限代码执行；这些验证也要检查单位、定义域、边界条件和多解情况。

采用逐步提示：先指出卡在哪一步，再给局部提示，最后才展示完整解答。根据学生的实际中间步骤判断概念混淆、建模错误、运算错误或审题错误；证据不足时让学生选择或确认。错题再练使用不同数字、表述或情境的同构变式，并在隔天检查迁移能力。

验收：生成题有独立答案验证；不合法条件和不可解题会被拦截；错误诊断可由教师抽样复核；模型不因用户错误推导而无条件赞同；所有用户可见题目保留生成版本与审核状态。

## 第五阶段：跨科全周期优化与效果验证

每日容量之外加入每日不同空闲时间、考试时间点、休息、任务依赖、预计耗时误差和个人目标。保留 FSRS 原始到期时间，以独立考前强化任务实现冲刺；漏学后重排未来剩余任务，不把所有欠账堆到第二天。计划不可行时显示时间缺口和取舍，而不承诺全部掌握。

通过小范围真实学生试用，比较不同策略的前测、延迟测验、实际考试表现、任务负担和放弃率。控制课程基础与自选偏差，不能把点击量或阅读时长当作提分证据。

验收：排期不会超过用户容量；依赖与考试边界满足约束；无法完成的目标被清楚说明；算法改动通过离线回放与真实试验，而不是只看演示数据。

## 持续工程要求

- 记录解析/检索/模型服务的错误率、时延、成本和排队时长，设置可行动的监控告警。
- 建立检索命中、引用支持度、生成题正确率与用户纠错的评测集；为错误内容提供撤回和重新生成机制。
- 处理模型提示注入、跨用户数据泄漏、上传滥用和资源耗尽；对外部服务发送最少必要内容。
- 验证桌面、手机、键盘、屏幕阅读器、低速网络和失败状态；真实学习内容的长公式与长文段也要纳入回归。
- 资源推荐以合法链接与明确授权内容为基础，分别检查代码、模型权重、教材、题库和视频的许可。

先后顺序可以随着用户验证调整，但「来源可核对、数据可恢复、建议能解释、效果可测」应贯穿所有阶段。
