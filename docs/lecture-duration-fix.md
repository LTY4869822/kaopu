# 长讲次时长限制修复

2026-11-05，用户的高等数学P3导入时提示“超过本地转写时长限制，或未返回有效时长”。

## 原因核验

对当前讲次 `BV1CAxaeHEeH?p=3` 只读取公开元信息：B站当前分P返回3941秒，已安装yt-dlp返回3940.692秒，约65分41秒。原本本地转写默认3600秒，在下载前被拒绝；此讲次的时长元信息有效。1080p视频估算186725257字节，低于现有256MB预算。

## 修改

- 本地转写与画面采集默认单讲上限统一为7200秒，处理超时统一为30分钟。
- 元信息及实际媒体时长均校验，7200秒硬上限保留；文件大小、帧数、并发预算维持原值。
- 非数字、布尔值、非有限数、零和负时长返回`DURATION_UNAVAILABLE`，与真实超限的`DURATION_LIMIT`区分。超限提示显示本次配置的分钟或秒数。
- 不新增外部元信息回退、不自动下载模型，不改账户或课程归属。

## 回归

最终`npm test`：220/220通过，0跳过。新增两条Python下载管线的离线回归，以及Node适配器的默认120分钟、动态错误上限、临时文件清理和诊断不泄露检查。

离线案例覆盖65分41秒、7200秒边界、超限下载前拒绝、缺失/NaN/正负无穷/布尔值/零/负数/字符串时长，及拒绝playlist/multi_video，保证单讲请求不会退回合集。

## 本机真实重试

测试通过后重新启动现有本地服务，恢复原账户会话，在用户已有讲次上点击“从链接导入”，没有创建重复讲次。第一次重试通过时长与语音处理，但导入转写时触发了另一条校验：整篇字幕只要含超过2个U+FFFD就被判为乱码。第一轮记录为`test-results/lecture-duration-fix/first-retry.json`。

本机ASR来源采用有界的稀疏识别异常标记校验：原本允许的0–2个标记保留，更多标记需同时满足不超过100个、占解码后字幕正文不超过0.5%。保留原始片段与回听提示；手动导入保持严格检查。许可仅由服务器已验证的本地ASR抓取路径传递，HTTP请求不能通过伪造provenance或开关启用。JSON解码后的控制符也会检查。

对应新增6组来源回归，覆盖数量与比例边界、JSON转义、HTTP伪造许可、外部来源限制、原文/时间/警告保留、持久化与失败重试。第一次真实重试失败后，没有把未通过校验的转写作为已导入来源；最终版本在同一讲次进行第二次重试。

第二次完整处理成功，状态为`completed`、无错误：1247段原文、48张采样画面全部识别、AI讲义101个细分内容段落及17个例题。5个U+FFFD仍原样保留；59个需回听核对的原文段落包含这些识别异常及语音模型原有的核对范围。监测从开始到完成约483秒。这不是转写正确率、讲义正确率或全视频板书覆盖率的评估。
