# 期末复习平台：研究依据与产品内核

研究日期：2026-11-04。本文区分「已核实的参考能力」与「本项目设计建议」；它不是已实现功能清单。实际交付范围以 README 和运行代码为准。

## 1. 要解决的任务

核心不是再给学生一份更长的总结，而是把「材料 → 考点 → 诊断 → 学习动作 → 检验 → 下一次安排」连起来。用户提出的资料过多、理解困难、背诵困难、考试分散、资源不足、理工科练习耗时，是同一条链路的不同断点。

额外需要验证的痛点假设：

- **不知道自己是不是真的会**：读懂答案不等于能独立做题，复习进度不能只统计阅读时长。
- **版本和范围不匹配**：同名课程的教材、老师、考纲可能不同；资源要标注适用章节和来源，不能凭热门程度推荐。
- **基础缺口隐藏**：不会积分可能是换元、导数或代数变形没掌握；应先找最小前置缺口。
- **错题重复但错误原因不同**：概念混淆、建模错误、运算错误与审题错误，需要不同干预。
- **计划一天没完成就崩掉**：允许实际可用时间变化，重排剩余任务，避免把所有欠账堆到第二天。
- **手机碎片时间和桌面深度学习脱节**：手机适合卡片、回忆与短测，电脑适合资料对照和完整推导。
- **临考焦虑造成过度计划**：首页只给一个清晰的下一步，并显示今天的合理上限。

这些是产品假设，不是已经完成的学生访谈结论。后续应访谈不同专业学生并记录考试成绩与学习行为，验证需求。

## 2. 开源项目与研究参考

| 参考 | 已核实能力 | 如何借鉴 | 边界 |
| --- | --- | --- | --- |
| [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs) | TypeScript 间隔复习工具，MIT | 接入真实调度库，保存逐次回忆评分和状态 | 记忆调度不能代表理解、解题能力；无个人数据时用默认参数 |
| [Docling](https://github.com/docling-project/docling) / [格式说明](https://docling-project.github.io/docling/usage/supported_formats/) | 多格式文档转统一结构，含 PDF、DOCX、PPTX，代码 MIT | 保留页码、标题、表格、片段身份，为来源回溯打基础 | 文档转换不等于考点识别；扫描件、公式和版式需要独立质量评估 |
| [RAGFlow](https://github.com/infiniflow/ragflow) | 文档检索、分块与有来源的回答，Apache-2.0 | 借鉴检索证据与引用链，不照搬整个部署体系 | 有引用不代表结论正确，仍应校验引用是否支持答案 |
| [pyBKT](https://github.com/CAHLR/pyBKT) / [论文](https://arxiv.org/abs/2105.00385) | 根据题目作答序列估计知识掌握情况，MIT | 后续研究知识点层面的掌握估计、滑失与猜测 | 需要可靠题目标签和足够数据；不能把未训练的模型包装为精准预测 |
| [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/accessibility) | 键盘导航、焦点管理及 ARIA 实践 | 弹窗、标签页等复杂交互采用成熟原语 | 应用仍须提供正确标签、对比度与移动端布局 |
| [shadcn/ui](https://github.com/shadcn-ui/ui) | 可组合、可修改的组件代码，MIT | 参考清晰的信息层级与组件组织，建立自己的视觉风格 | 组件库并不自动提供好的学习流程 |

版本注意：研究时 [ts-fsrs Quick start](https://open-spaced-repetition.github.io/ts-fsrs/guide/quick-start) 要求 Node.js 24+，当前 v6 使用异步 `DefaultScheduler()`，默认算法为 FSRS-7。实现时必须核对实际安装版本及类型声明，不混用旧版 `fsrs()` 接口与新版文档；如使用旧版，应锁定版本并明确标注。

许可：MIT 项目再分发需保留相应版权和许可文本；Apache-2.0 项目应保留许可、适用的 NOTICE 等信息并遵守修改标注要求。研究参考不意味着本项目已经集成该项目。模型权重、字体、题库、图片、教材的授权与代码许可应分别检查。参考 [Radix 许可](https://github.com/radix-ui/primitives/blob/main/LICENSE)、[shadcn 许可](https://github.com/shadcn-ui/ui/blob/main/LICENSE.md)、[RAGFlow 许可](https://github.com/infiniflow/ragflow/blob/main/LICENSE)。

学习方式依据：Karpicke 与 Blunt 的实验比较了检索练习和精细加工学习，支持在学习后主动回忆，而不是仅仅反复阅读。产品中的「先答再看」「解释给自己听」「隔天重做」由此得到启发，但不能直接声称对所有专业、所有考试都有相同提升幅度。[原论文](https://doi.org/10.1126/science.1199327)、[作者公开论文](https://learninglab.psych.purdue.edu/downloads/2011/2011_Karpicke_Blunt_Science.pdf)。

## 3. 自己的内核：以考试截止时间为约束的学习闭环

以下为本项目提出的设计，不是上述开源库自带功能，也不是经过实验验证的最优算法。

### 3.1 资料可信度与考点证据

每条知识点维护：课程、章节、先修概念、原文件、定位信息、提取片段、用户确认的考纲权重。重点来源优先级由用户设定，例如老师划定范围、课程大纲、历年题、课件；不要把词频直接称为「必考概率」。

第一版可以实现可解释的词项检索和摘录；只有实际接入生成模型后才能标为 AI 讲解。每个答案区分「原文证据」「解释」「推断」，证据不足时明确显示未找到支持。

资料不足时推荐精确到知识点的短资源，而不是整门长课。外部资源先以链接与适用范围组织，避免未经授权复制题库。比如 MIT OCW 的一般许可包含非商业和相同方式共享约束，不能把「免费可看」理解为任意商用再分发。[MIT OCW 使用条款](https://www.ocw.mit.edu/pages/privacy-and-terms-of-use/)。

### 3.2 分开估计记忆与解题掌握

- **记忆状态**：回忆卡使用 FSRS，保留评分、时间、稳定性及下次到期时间。用户必须先尝试回忆再自评。
- **解题状态**：使用独立的练习记录，保留正确性、使用提示、耗时、题型、知识点和错误原因。初版可采用带先验的正确率估计，不冒充已训练的 BKT。
- **掌握证据**：无提示、不同变式、隔天再次答对比刚看完答案更有说服力；不能通过重复点同一题无限提高掌握度。
- **理工科步骤**：概念直觉 → 最小例题 → 分步提示 → 独立变式 → 错因回流。没有接入符号验证或可运行求解器时，不宣称能验证任意推导。

### 3.3 跨科安排

把学习任务分成 15–30 分钟小块。每块具有预计耗时、截止日期、课程权重、当前掌握缺口、是否到期、先修条件。每日可用分钟数是硬约束，考试日期是硬边界。

一个适合第一版、可解释且可测试的优先分数：

`priority = courseWeight × gap × urgency × reviewBoost / sqrt(estimatedMinutes)`

其中 `gap` 来自已有练习证据；`urgency` 随临考接近上升但设上限；`reviewBoost` 提升到期卡片与错题；未知项使用公开默认值。这个分数只是启发式策略，不是考试提分概率。再按先修依赖和每日容量分配，保留休息余量；若排不完，展示缺口并让用户调整目标/时间，而不是悄悄超额安排。

FSRS 的原始到期时间与考前强化练习应分别保存。临考加练可以增加一个任务，不要直接篡改记忆模型输出。考试结束后停止冲刺任务，用户可以选择继续长期记忆。

### 3.4 信息架构

1. **今日复习**：一个下一步、今日容量、少量优先任务和最近考试。
2. **课程与资料**：先选课程再上传，能看到解析状态、来源和提取失败原因。
3. **理解与练习**：解释、提示、提交、错因、下一步在一个上下文中完成。
4. **记忆卡片**：可翻面、自评、显示合理的下次安排。
5. **复习计划**：修改考试日期和每日时间后重新安排，展示未能安排的任务。

视觉建议：温暖的浅色背景、清晰的深色文字、单一草木绿主色；桌面侧栏，手机底部主导航；操作按钮大于装饰元素；完成反馈轻量，尊重减少动画设置。不要用没有来源的精确「提分预测」装饰界面。

## 4. 实现与验证路线

**可运行首版**：真实文件上传与文本提取、明确的来源检索、可编辑课程/考试、容量受限排期、题目提交与错题保存、真实间隔复习状态、持久化、响应式界面。没有模型服务时仍可完成上述确定性流程。

**模型增强阶段**：加入独立解析队列、OCR/公式质量指标、向量与词项混合检索、带引用的生成讲解、按知识点出题和专家抽样审核；密钥仅在服务端，不能写进前端包。

**多人产品阶段**：账号与课程隔离、对象存储、数据库迁移、备份恢复、删除机制、异步任务限流、可观测性、跨设备同步与权限验证。前端响应式不等于已完成跨设备同步。

验收应覆盖：

- PDF/DOCX/PPTX 提取结果与真实文本相符；扫描 PDF 显示需要 OCR，不返回伪造成功。
- 检索引用能回到实际存在的片段；无命中不编造来源。
- 排期不超过日容量、不安排到已过期考试之后、相同输入输出稳定、临近考试得到合理优先级。
- 评分后到期状态持久化；重复提交有去重策略，刷新页面不会丢记录。
- 练习提交有实际判分、解释和错题回流；未作答不能计作掌握。
- 390px 手机与桌面均无横向溢出；弹窗可用键盘关闭，表单有标签，错误信息可读。
- 评价学习效果时采用真实的前测/后测与延迟测验；点击率、看完率和自评不等于成绩提升。
