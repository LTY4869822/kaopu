# 手写笔记：识别、归档与逐页校对

更新日期：2026-11-05。

可以把手写笔记照片或扫描 PDF 导入课程资料。识别后的文字可以阅读、排版公式，并继续用于资料要点与课程复习；原件保留，识别稿始终提供校对入口。识别能力不等于每个手写字、负号或上下标都可靠。

## 学生使用流程

1. 在首页选择文件，或把笔记拖进导入区。支持 JPG／JPEG、PNG、WebP，也可以先用手机扫描为 PDF。文件选择只进入待分析列表，点击“开始分析”后才上传处理；已确定课程时也可从「我的课程 → 目标课程 → 手写笔记」直接归档。
2. 普通照片可以保留“自动读取”；照片会使用配置的视觉模型。手写扫描 PDF 请在“读取方式”中选择“手写笔记 / 看图识别”，按页读取画面。普通“版式增强 / OCR”主要是文档结构与扫描文字解析，不应将其效果当成手写公式已准确识别。
3. 系统按文件名、识别文字和已有课程判断归属。线索充分时归入对应课程；不足时会显示“帮我确认一下科目”，选择已有课程或新建一门，再点“确认归档”。例如高数、线代都有相近符号时，需要学生确认。
4. 从结果进入课程工作台，打开这份资料，查看“原件与识别文字”。照片可以放大原图；PDF 提供对应页的原文件定位。识别文字按原件页码排列，公式使用数学排版显示。
5. 点击“校对这一页”，对照原件修正文字、公式或缺失符号，再点“保存校对”。看不清的位置保留“[无法辨认]”。全部页面都保存确认后，资料从“待校对”变为“已校对”。

“确认归档”确认的是课程归属，“保存校对”确认的是页面内容，两者不是同一个状态。归档成功的识别稿仍可能需要核对。

## 格式和处理限制

| 项目 | 当前行为 |
| --- | --- |
| 单个文件 | 最多20MB |
| 笔记照片 | JPG／JPEG、PNG、静态WebP；必须包含可解码像素，不能只修改扩展名 |
| 原图尺寸 | 最多2500万像素；异常尺寸或损坏图片会拒绝，部分高位深PNG还受解码大小限制 |
| 手写识别PDF | 每份1–8页，超过8页需拆分；不会只读取前几页并冒充整份完成 |
| 单页文字 | 最多16,000字符，校对编辑器使用同一上限 |
| 手机方向 | 原生解码会处理照片EXIF方向，识别前转换为方向正确的图片 |
| 识别过程 | 图片按受控尺寸生成临时内联输入，PDF逐页渲染；任一页失败不返回一份貌似完整的半成品 |

拍摄时尽量让纸张完整入镜、文字清晰，减少阴影、反光、倾斜与手指遮挡。多页笔记应按页拍摄或组成短PDF，不宜把很多页拼成一张很长的小字图片。

## 模型连接和原件保存

手写识别复用现有“板书识别”的视觉模型连接，不需要另建一套服务。可以在“网课精读 → 模型设置 → 板书识别”中检查连接并完成看图测试；只有纯文字能力的模型无法承担照片识别。未配置时接口会明确提示配置，不返回伪造的识别结果。

照片及扫描页会发送给配置的视觉服务用于识别，不经过公共图床。原文件保存在运行考谱服务的设备中，课程工作台通过需要登录的原文件接口查看；密钥不进入前端、原文件链接或识别稿。

后台仍保留普通文档读取路径：含文字的PDF、Word、PPT可先本机解析，扫描PDF可用已有Docling OCR。只有照片或明确选择“手写笔记 / 看图识别”的文件才走手写视觉识别流程。

## 识别提示、校对和版本保护

识别结果包含以下状态：

- `recognition.kind: "handwriting"`：此资料来自看图转录。
- `recognition.needsReview: true`：还有页面未经学生确认。全部页面保存校对后才改为`false`。
- `recognition.pages[].warnings`：模型指出的不确定位置，来自识别响应的`uncertainties`。它不是完整的错字清单；没有提示也可能有错误。
- `recognition.pages[].reviewed`：学生是否保存确认了这一页。它不表示模型达到某个准确率。
- `recognition.revision`：当前识别文字的修订版本，用于避免多个窗口互相覆盖。

校对可使用`$…$`或`$$…$$`排版公式。原图、PDF及最初识别稿保留；页面保存后能展开“查看最初识别稿”。原识别提示也保留，以便追溯。

保存文字会更新当前页的阅读片段及资料要点。若正文发生变化，依赖旧资料的题目和试卷不再作为当前有效练习；清理前会把旧正文、修订版本、相关题目、作答、试卷及模板保存到私有修订历史。资料中有历史时可下载查看，已完成的作答和评分不会无声丢失。历史只能查阅，不恢复为可继续作答的旧试卷，也不触发新的掌握度计分；课程此前累计的掌握度不会因此被自动回退。建议开始练习前先完成笔记校对。页面归属和原文件不因此被改写。

如果另一窗口先保存了资料，当前窗口提交旧`revision`会收到HTTP409。界面保留本次编辑文字并显示错误，服务端不覆盖较新的版本。先复制保留草稿，刷新到最新内容后再对照合并保存；刷新本身不会替学生自动合并草稿。

首页的自动／手写识别入口按原文件字节判断重复。完全相同的文件再次上传会复用原资料，保留已有课程归属、逐页确认状态与人工修订，不重新识别覆盖。名字相同但内容改变的文件不视为同一文件。

## 接口约定

接口均沿用现有账户保护。供本机开发与回归验证使用：

- `GET /api/document-parser`：`handwritingAvailable`表示是否已配置视觉服务，不是当前文件的识别成功或准确证明。
- `POST /api/documents/auto`：multipart字段`file`、`parseMode`；照片在`auto`模式使用视觉识别，手写PDF使用`handwriting`模式。返回课程分类与资料对象；不确定分类需要学生确认。
- `POST /api/documents`：multipart另带已有`courseId`，把识别结果保存到指定课程。
- `PUT /api/documents/:id/recognition`：JSON包含已有`page`、1–16,000字符的`text`和当前`revision`。版本不匹配返回409；资料不存在返回404。页码由原件绑定，不能自行添加不存在的页。
- `GET /api/documents/:id/recognition-history`：下载这份资料的旧修订与相关学习记录，仅供历史查阅。完整快照留在私有状态中，普通资料对象只提供历史编号、修订号、时间与数量。
- `GET /api/documents/:id/original`：读取保留的原件。PDF支持浏览器`#page=N`定位；不会暴露服务端文件路径。

解析结果沿用`chunks`与`structure`，页码由本机生成和校验。`parser.engine`为`vision`、`ocr`为`true`、`handwriting`为`true`；`formula`保持`false`，表示没有“公式已经准确验证”的承诺，虽可转录和排版公式，仍需对照原件核查。

## 本轮真实验证

使用[UBC官方公开手写微积分笔记](https://personal.math.ubc.ca/~colesmp/teaching/M110/Pencasts/1_7_Limit_definition_of_derivative.pdf)中的1页进行实测：PNG照片输入和PDF输入均完成视觉识别，并归入“高等数学”课程资料。单页本次识别约4秒；这是一个样本的观察，不能当作所有字迹、网络和模型条件下的速度基准。

首次识别稿遗漏了首步的双负号，其他推导内容仍有保留。这正是逐页原件对照与人工修订入口要处理的问题，不能因为文字提取成功就宣称数学推导完全正确。模糊字迹、箭头、划改、图形、分式、正负号及上下标都应重点核对。

最终串行完整测试228/228通过，生产构建通过。手写解析的专项测试还覆盖真实图片解码、实际PDF渲染、手机旋转信息、格式伪装与损坏像素、页数上限、取消／超时、响应大小、模型配置快照和安全错误；修订测试覆盖旧版学习记录归档、下载、原件保留及公开状态不泄漏归档答案。真实浏览器已确认课程内查看、负号校对保存、刷新后重新阅读及390px手机无横向溢出；截图见`docs/screenshots/handwriting-reviewed-desktop.png`。真实测试记录用于证明流程可用，不用于宣称任意手写笔记均能完整正确识别。
