# 完善卡帕西知识工作流实施计划

## Context

当前项目已经具备 B 站链接/分P解析、公开字幕、AI 讲义、真实关键帧、课程资料归档、账户工作区隔离和 Markdown 文件树。实际缺口是：Raw 只是可覆盖的文本镜像，上传原件与 B 站原始响应没有统一进入不可变来源层；视频仅在可选抽帧时临时下载且随后删除；AI 分块缺少持久检查点；知识库没有完整的 Schema/index/log/query/lint；Output 尚未形成可复用、可检索的本地产物。

本次保留 `state.json`、`lessons.json` 作为运行时真源，不推翻现有课程、网课和账户体系。采用轻量默认链路：只读公开字幕时不额外下载视频；启用关键帧时下载真实视频并永久归档，后续抽帧和识别重试复用本地原件。视频下载、抽帧仍明确属于可选服务端能力，不把 Python、yt-dlp、PyAV 或视觉模型伪装成所有用户默认已具备的条件。

## 实施方案

### 1. 建立不可变 Raw 来源层，并保留现有 Markdown 视图

- 新增 `server/raw-store.mjs`，在每个用户工作区的 `knowledge/_raw/<courseId>/<sourceId>/<artifactId>/` 保存原始字节和 `manifest.json`。课程使用稳定 ID，课程改名不搬移原件。
- B 站以来源规范化后的 BV+分P确定 `sourceId`；上传文件以原始字节哈希去重。每个 artifact 记录类型、MIME、大小、SHA-256、来源定位、摄取时间、提取器版本和引用关系，不记录 Cookie、密钥或临时媒体签名 URL。
- 写入采用临时文件、哈希校验、排他创建/原子改名；同内容重试复用，已存在但哈希不符直接报错，绝不覆盖。JSON 中只保存 `rawRef`。
- 上传 PDF/DOCX/PPTX/TXT/Markdown/图片时，在解析前提交 Raw；粘贴文字、字幕也在解析前提交。`bilibili-subtitles.mjs` 返回原始字幕载荷及经过白名单裁剪的视频/分P元数据，由 `lessons.mjs` 统一归档。
- 现有 `科目/raw/*.md` 继续作为可覆盖、可再生的 Obsidian 阅读视图，并链接对应 `rawRef`；不可变原件不参与镜像清理。现有 `lesson-visual` 中的 JPEG 和证据 manifest 作为关键帧原始记录登记 hash，`科目/resources` 仍只是复制视图，避免重复存图。
- 历史 `documents/*.bin` 可按原字节回填；历史讲次只有 cues 时标记 `legacy-derived`，不得伪造成平台原始字幕或原始视频。

### 2. 稳定“真实视频→AI 消化→Wiki→关键帧”链路

- 在 `lessons.mjs` 为 AI 分块增加 `analysisCheckpoint`：记录来源/模型指纹、已完成分块和下一块位置，每块成功即保存；只有指纹完全一致才续用，来源或模型变化则作废。失败保留 Raw、cues、已采关键帧及检查点，重试不重复下载和重算成功分块。
- 导入时校验 `autoPublish=true` 必须带有效 `analyzeMode`，避免停留在 `ready` 却不归档也不报错。来源获取、采帧、识别、分析、归档分别记录最后失败阶段和可重试状态。
- 修改 `lesson-vision.mjs` 与 `scripts/extract-lecture-frames.py`：启用画面处理时，将下载的真实视频先提交 Raw，再以其本地路径抽帧；识别或抽帧失败也不删除已归档视频。后续采帧、补采和识别优先使用 `rawRef`，仅显式重新获取才访问网络。继续执行现有时长、大小、帧数、JPEG hash 和超时限制。
- 公开字幕仍走现有纯 Node 默认路径；无字幕、无下载依赖、无视觉模型时分别给出明确错误和可用替代操作，不静默降级为假关键帧或假 AI 笔记。
- 在来源完成、分析完成、视觉状态完成、归档和 Output 提交后触发知识库同步，不再依赖用户手动打开 `tree?refresh=1`；进度轮询的中间保存不做全量镜像。

### 3. 补齐 Karpathy Wiki 的 Schema、索引、日志、查询和 Lint

- 扩展 `knowledge-base.mjs`，在用户 vault 根生成固定的 `SCHEMA.md`、全局 `index.md` 和追加式 `log.md`；课程索引继续汇总讲次、资料和概念页。Wiki 文件使用稳定来源/讲次/资料 ID，保留 `[[笔记名]]` 双链和 cue/chunk/frame 引用。
- 每次 ingest、AI 消化、query、lint 和 Output 生成记录阶段、来源引用、结果或错误；日志只追加，不作为另一套运行时数据源。
- 新增 `POST /api/knowledge/query`：请求为 `{courseId, question, save?}`，服务先读取课程索引，再检索限定数量的相关 Wiki，调用现有 OpenAI-compatible provider，返回 `{answer, citations[]}`；引用必须映射到真实 noteId 及 cue/chunk/frame。`save=true` 的有价值问答写回 JSON 并生成互链 Wiki 页。
- 新增 `POST /api/knowledge/lint`：检查 Raw hash、断链、孤儿页、索引陈旧、资源缺失和 Output 来源过期，返回结构化报告并生成可读 Markdown；只修复可再生视图，不修改 Raw。
- 普通 PDF、DOCX、TXT、Markdown、图片资料复用现有解析结果和课程工作台 AI 任务生成结构化 Wiki，不另建一套文档处理管线。

### 4. 落地 Output 层与前端入口

- 扩展现有 `course-studio.mjs` 的 job/artifact，而不新增独立任务框架：在 `notes/chat/revise` 之外增加 `review`、`exam-checklist`，分别生成复习资料和带引用的考点清单。输入使用与 Wiki 相同的 JSON 笔记及来源引用，模型提示和响应 schema 强制引用真实来源。
- artifact 增加 `kind`、`sourceNoteIds`、`sourceFingerprints` 和 revision。成功后将 Markdown 持久化为 `科目/output/<稳定产物名>/r<n>.md`；源 Wiki 变化只标记 `stale`，历史版本不覆盖。PDF/DOCX 继续复用现有导出器，并在首次导出时保存对应版本。
- `CourseStudio.tsx` 增加“复习资料 / 考点清单”生成入口，复用现有轮询、失败重试、产物架、阅读器和导出按钮；`KnowledgeBase.tsx` 默认展开 output，并补充 Output、Schema、lint 状态和 stale 提示。现有 tree/file/asset 路径校验与路由顺序保持不变。

### 5. 提供三个真正可调用的项目级本地 Skill

在应用根目录创建：

- `.trae/skills/shifen-raw/SKILL.md`：识别 B 站链接或本地资料后调用导入/摄取 API，核验 rawRef、hash、分P、失败阶段和重试方式。
- `.trae/skills/shifen-wiki/SKILL.md`：调用分析、知识库同步、query 和 lint，要求先索引、后相关页、带引用回写，禁止修改 Raw。
- `.trae/skills/shifen-output/SKILL.md`：调用课程工作台 `review`/`exam-checklist`、轮询和导出，核验 Output 的 Wiki 引用与 stale 状态。

三个 Skill 使用合法 frontmatter，名称与目录一致，只编排真实后端 API，不复制运行时逻辑，也不以文档代替功能实现。

### 6. 用户隔离、兼容与备份

- 沿用 `data/users/<accountId>` 工作区，所有 Raw、Wiki、resources、Output、日志和模型任务均只在当前工作区读写。
- 将 B 站登录 session 改为用户工作区内存储，避免共享根目录 Cookie；原全局 session 不自动复制到其他账户。
- 保持旧 JSON 可直接启动，旧 API 字段只增不减。`backup.mjs` 显式纳入不可变 Raw、必要的 Output/日志和每用户 B 站 session，继续排除可再生的 Markdown/JPEG 镜像，恢复时校验 hash 和路径。

## 关键修改文件

- 后端：`server/raw-store.mjs`、`server/knowledge-base.mjs`、`server/lessons.mjs`、`server/bilibili-subtitles.mjs`、`server/lesson-vision.mjs`、`server/local-video-source.mjs`、`server/course-studio.mjs`、`server/index.mjs`、`server/bilibili-auth.mjs`、`server/backup.mjs`
- 视频脚本：`scripts/extract-lecture-frames.py`，必要时小幅调整 `scripts/transcribe-course.py` 以返回可归档原始结果
- 前端：`src/CourseStudio.tsx`、`src/KnowledgeBase.tsx`、`src/LessonStudio.tsx` 及对应类型和样式
- 测试：`tests/knowledge-base.test.mjs`、`tests/lessons.test.mjs`、`tests/lesson-vision.test.mjs`、`tests/course-studio.test.mjs`，新增 Raw/Output 测试及离线 UI smoke
- 本地能力：`.trae/skills/shifen-{raw,wiki,output}/SKILL.md`

## 验证

1. 单元测试覆盖 Raw 不可变、哈希去重、临时文件崩溃恢复、镜像刷新不删除原件、两个用户完全隔离、旧数据迁移和备份恢复。
2. 用 fake fetch/假模型/假子进程验证：公开字幕原始载荷归档；AI 中途失败后续跑；自动归档参数校验；视频只下载一次；抽帧失败保留视频；识别失败保留 JPEG；无字幕/无工具/无模型错误明确。
3. 验证 PDF、DOCX、TXT、Markdown、图片与粘贴文字均形成 Raw→Wiki，Wiki 双链和引用有效，lint 能发现断链/缺图/陈旧 Output，query 确实先读索引且不能伪造引用。
4. 验证复习资料和考点清单落盘到 output，重试幂等、修订产生新版本、源变化标 stale，Markdown/PDF/DOCX 可导出且路径穿越仍被拒绝。
5. 运行 `npm test`、`npm run build` 和相关现有 UI smoke；新增离线端到端 smoke，以 B 站夹具和合成模型完成 Raw→Wiki→JPEG→Output，并检查前端轮询、重试、文件树和导出。
6. 环境具备真实模型与可选视频依赖时，再用一个有时长/大小上限的公开 B 站分P做人工端到端验收；若环境缺少依赖，只报告该项未执行，不用 mock 结果冒充真实视频验证。
